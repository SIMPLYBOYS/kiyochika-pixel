# 清親《東京名所図》— 光線画像素遊戲

小林清親在 1876 到 1881 年畫了一批東京。瓦斯燈、火災、月、雨後的橋——
浮世繪最後一代的畫家，用西洋的明暗畫他每天走過的城市，後人叫它「光線画」。
這個專案把那批畫放回它們被畫的地點上。

系列前三作：[東海道五十三次](https://github.com/SIMPLYBOYS/tokaido-pixel)（線性旅程）、
[名所江戶百景](https://github.com/SIMPLYBOYS/edo-hyakkei)（面狀＋四季）、東京二十景（川瀨巴水）。
這一作與江戶百景共用同一套地圖做法——**一套真實座標，兩層皮**。
江戶百景的滑桿兩端是 1858 與 2026，這裡是 1880 與 2026。

**目前做到 Phase 2（素材 pipeline）。地圖可以看、可以點，像素版已產出，還沒有玩法。**

每一筆 `subject` 都帶 `place.anchor`，說明它是怎麼來的：

```json
"anchor": { "how": "osm-cluster×4", "name": "銀座",
            "osm": "node/6271990033", "kind": "station", "confidence": "district" }
```

`confidence` 四級：`osm`／`wikidata` ＝ 指到題名說的那個地物本身；
`district` ＝ 只指到那一帶（駅名或町名）；`low` ＝ 依據有明說的缺口。
Phase 3 要拿畫面收斂的就是 `district` 那 31 幅。

## 兩條規則

**斷詞只從題名來，座標只從 OSM／Wikidata 來。**
加了題名以外的知識，根據就變成「我的印象」，無從查證。
所以每個座標都指得出是哪個 OSM 元素或哪個 Wikidata QID 給的。

**沒有依據就留空。** `places.json` 的每一筆都要有 `source` 與 `why`；
寫不出 `why` 的進 `_unresolved`，把理由寫清楚：

> `12` 細目表寫「駿賀町」。OSM 只有神田駿河台（不同地方），Wikidata 查無日本橋駿河町。
> ⛔ 不套用「駿河町＝今の日本橋室町」這個未查證的等式。

> `66` 「柳原」＝神田柳原（神田川南岸）。⛔ OSM 的柳原一丁目・柳原橋全在足立区，
> 距神田 6km，用了就是「看起來合理」的錯。

空白是資訊，猜出來的座標不是。目前未定位 10 筆：12、28、31、45、48、51、53、54、65、66。

## 五個「看起來合理」的錯

日文地名比對會安靜地給出合理但錯誤的答案。以下每一條都真的發生過。

**一、前綴贏過真地名。** 「東京銀座街日報社」比中的是「東京」，於是三幅畫全指到東京駅。
前綴要**剝掉而且排除在候選之外**——只做其中一件，它會再贏一次。這個錯犯了兩次。

**二、子字串。** 「大川端石原橋」比中「原橋」（世田谷），「ためいけ」比中「いけ」。
判準是前一個字的文字種類：同種類代表切在詞中間。
只對兩字名執行——三字以上的地名不會是別的詞的尾巴，一律執行會把増上寺、永代橋也擋掉。

**三、長度不是好判準，位置才是。** 第一版用「兩字以下一律不採」擋子字串，69 幅只中 10 幅：
日本地名本來就多半是兩個字（銀座・高輪・今戸・橋場・蔵前・大森）。
清親的題名幾乎都以地名開頭，所以**先頭比中的兩字名可信，句中冒出來的不可信**。

**四、同名多筆有兩種，混在一起就會誤判。** 隅田川 40 筆是同一條河被切成很多段（散佈 20km），
八雲神社 10 筆是十個不同的神社。前者要合併成一個地物，後者不能。判準是叢集直徑。
合併後取重心，但**種類要從最可信的那筆拿**：日本橋六筆裡有橋也有地鐵站，
取到站就變成「日本橋夜」畫的是地鐵站。

**五、只有眼睛抓得到的那個。** 「萬代橋朝日出」比到 OSM `way/1105144393`，在世田谷。
assert 過得了，因為它在畫框內。抓出來的方法是把 59 個點畫在水系上看：
其餘 68 幅全在舊市街與隅田川一帶，只有它落在西邊 4 公里的郊區，
而同一叢還有一座已因同樣理由否掉的常盤橋——那是戰後住宅區的橋群。

所以 `check-subjects.py` 是必要驗收不是加分項。
自動檢查抓得到「掉出畫框」，抓不到「落在錯的區」。

## 裁切：三個坑

**一、外圈的中位數不是背景色。** 這些頁的**上緣是襯紙（米色）、下緣才是灰底**，
從整圈取中位數會落在哪一邊要看那一頁——落錯就整個判定反過來（44 只留下 681 列）。
灰底**只從最底部 1.5% 取樣**，那裡一律是掃描台。

**二、單一列掉到門檻下就切斷連續段。** 取最長連續段是對的（比例尺與台紙之間隔著
一道灰，用 first/last 會跨過去把尺收進來），但紙上一道摺痕就會製造假縫。
先做 1-D 閉合再取最長段——**而補多大是候選參數之一，不是定值**（見下）。

**三、保險絲要擋崩潰，不要擋正常裁切。** 第一版設「裁掉超過一半就不採用」，
但和紙本來就只佔台紙約 39% ⇒ 每一幅正常的裁切都被擋掉，全部退回整頁。

🔑 **結論不是「調出一組萬用參數」，是「跑幾組、挑一個」。**
補縫補得大，比例尺被連進來；補得小，摺痕把台紙切成兩半。兩邊都試過，各壞一半。
但**整本畫帖的版面是一致的**——和紙一律 1400–1800px 寬（69 幅的中位數 1640×1103），
而這個先驗**來自資料本身**，可以拿它當選擇規則。

## 出版日期為什麼只有 4 筆

御届確實印在紙邊：id 1 是「明治九年八月廿一日御届」＝ 1876 年 8 月 21 日，
正好是光線画首發的那個月。但版子本身有三種狀態：

- **印齊**（1、21、61、63）——可以當日期用。
- **整組空白**（11、37、58、59）：「明治　年　月　日」。不是讀不到，是版上就沒有。
- 🔑 **只刻到十位**（8、60）：版上是「**明治十　年**」，個位留空——那是留給每一刷填的。
  只知道落在明治十X年（1877–1886），⛔ 不能當年份用。

🔴 **畫面上印的日期不一定是出版日。** 60 兩国大火浅草橋 的畫面印著
「明治十四年一月廿六日出火」——那是**火災發生日**。Phase 0 曾把它當成出版年記成 1881，
已更正（它的奧付其實只有十位）。同一場火的另外兩幅（61、63）奧付印著完整的
「明治十四年」＝ 1881，與火災同年，互相佐證。

🔑 **畫帖的排列不是編年的**：1＝1876、21＝1879、61／63＝1881。⛔ 不可用畫帖順序推日期。

其餘各幅未判讀。工具已就位，但六幅一張時看得出奧付結構、讀不準年份的個位，
要逐幅放大——那是資料輸入工，不是工程問題。

## 當時的市街圖為什麼只有一個連結

計畫本來指定 1880/1882 年的《東京方角一覽地圖》。查下來三條路：

- **NDL 有藏也數位化了**（pid 14433865／14433926），但 IIIF 回 `checkResult: NG`
  ＝ **非公開**（館內或圖書館送信限定）。拿不到。
- **David Rumsey 有一張 1882《東京繪圖》**，17098×12188、IIIF 全開，原本藏於
  UC Berkeley 東亞圖書館。但 Cartography Associates 對**掃描**主張著作權（CC BY-NC-SA）
  ⇒ 收進這個 MIT ＋ 公有領域的 repo 會多一個 NC 的角落。**只連結，不下載**——
  連結不是重製。要不要真的用它是 Aaron 的決定，同 Phase 0 對 MFA Boston 的處置。
- **明治迅速測図（1880–86）沒查**：它是實測圖、有正確的地理參照，
  適合的用法是**對位疊圖**而不是「當文獻用」，那是另一個決定。

🔴 中間踩了一個假陽性，記在 `data/reference-maps.json` 裡避免重犯：
我從 NDL 的**書目頁**刮 `dl.ndl.go.jp/pid/NNN` 當作該書目的數位版，但書目頁會連到
**別的館藏**——pid 1301528 拉出來是芳年的《新撰東錦絵》，不是地圖。
而掃描結果還一併報了尺寸與頁數，看起來完全合理。
判準：**只認「搜尋結果的 link 本身就是數位館藏」，不要從頁面上刮 pid。**

## Phase 1 踩到的三個

**一、空心圓的中心是洞。** 座標只定到「那一帶」的 32 個點畫成空心，看起來對，
但 SVG 的 `fill:none` 不接 hit-test——點下去會穿過去打到底下的地形圖。
一半以上的標記只有那圈 2px 的線點得到。`pointer-events:all` 一行。

**二、抄過來的 CSS 帶著它原本的假設。** HUD 沿用 edo-hyakkei 的漸層背景，
那邊地圖上緣是海（深色），這邊是米色的陸地——同一段 CSS 在這張圖上等於白字印在白紙上。

**三、面板的圖直接連 NDL 的 IIIF，被回 429。** 那次是我們自己當天抓太多，
但道理不變：上線之後**每個玩家開一次面板就打 NDL 一次**。圖進 repo，執行期不依賴別人的伺服器。

（測試也踩了一個，那不是產品的錯：Playwright 點 `.mark` 會打到 `<g>` 的 bbox 中心，
而 bbox 含右邊那條景名，中心落在標籤那一半的空白上。改點圓本身。）
