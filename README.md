# 清親《東京名所図》— 光線画像素遊戲

小林清親在 1876 到 1881 年畫了一批東京。瓦斯燈、火災、月、雨後的橋——
浮世繪最後一代的畫家，用西洋的明暗畫他每天走過的城市，後人叫它「光線画」。
這個專案把那批畫放回它們被畫的地點上。

系列前三作：[東海道五十三次](https://github.com/SIMPLYBOYS/tokaido-pixel)（線性旅程）、
[名所江戶百景](https://github.com/SIMPLYBOYS/edo-hyakkei)（面狀＋四季）、東京二十景（川瀨巴水）。
這一作與江戶百景共用同一套地圖做法——**一套真實座標，兩層皮**。
江戶百景的滑桿兩端是 1858 與 2026，這裡是 1880 與 2026。

**目前做到 Phase 0（素材與資料建檔）。還沒有遊戲。**

```

座標   59/69（OSM 19・Wikidata 8・街區級 31・低信心 1）；未定位 10，理由逐條寫在資料裡
```

## 跑起來

零依賴（標準庫 ＋ Pillow）、零 build step。順序不能跳。

```bash
python3 tools/fetch-ndl.py --download      # 84 筆骨架 → data/views.json；2400px 整頁 → research/ndl/
python3 tools/fetch-gazetteer.py           # OSM 具名地物 23,565 筆 → data/geo/gazetteer.json
python3 tools/derive-subject.py --write    # 題名裡的地名 → subject 座標
python3 tools/check-subjects.py            # 把座標畫在水系上目視 ← 這步不能省，見下
python3 tools/fetch-colophon.py --sheet 4  # 裁出御届欄，拼成判讀用的表
python3 tools/fetch-commons.py --sheet     # Commons 側交叉比對（不是主素材）
```

`fetch-ndl.py` 重跑不會洗掉座標——它只重建自己產生的欄位（題名／出處／頁碼／收錄與否），
其餘原地帶過來。**第一版不是這樣：重跑一次就把 59 個查證過的座標清成 null，而且不報錯。**

## 資料

```
data/
  views.json         84 筆。include=false 的 15 筆留著不刪——刪了下次盤點又會把它們找回來
  places.json        人工定位的座標（機器不覆寫）
  published.json     人工判讀的出版年月（機器不覆寫）
  inventory.json     Commons 盤點結果，交叉比對用
  geo/gazetteer.json OSM 具名地物索引（4.8MB）
  geo/modern.json    街圖向量，從 edo-hyakkei 複製（1.8MB，ODbL）
research/            不進 build：ndl/ 整頁 101MB、colophon/ 奧付裁切、_subjects.png 目視驗收圖
```

每一筆 `subject` 都帶 `place.anchor`，說明它是怎麼來的：

```json
"anchor": { "how": "osm-cluster×4", "name": "銀座",
            "osm": "node/6271990033", "kind": "station", "confidence": "district" }
```

`confidence` 四級：`osm`／`wikidata` ＝ 指到題名說的那個地物本身；
`district` ＝ 只指到那一帶（駅名或町名）；`low` ＝ 依據有明說的缺口。
Phase 3 要拿畫面收斂的就是 `district` 那 31 幅。

## 兩條規則

**斷詞只從題名來，座標只從 OSM／Wikidata 來。**
加了題名以外的知識，根據就變成「我的印象」，無從查證。
所以每個座標都指得出是哪個 OSM 元素或哪個 Wikidata QID 給的。

**沒有依據就留空。** `places.json` 的每一筆都要有 `source` 與 `why`；
寫不出 `why` 的進 `_unresolved`，把理由寫清楚：

> `12` 細目表寫「駿賀町」。OSM 只有神田駿河台（不同地方），Wikidata 查無日本橋駿河町。
> ⛔ 不套用「駿河町＝今の日本橋室町」這個未查證的等式。

> `66` 「柳原」＝神田柳原（神田川南岸）。⛔ OSM 的柳原一丁目・柳原橋全在足立区，
> 距神田 6km，用了就是「看起來合理」的錯。

空白是資訊，猜出來的座標不是。目前未定位 10 筆：12、28、31、45、48、51、53、54、65、66。

## 五個「看起來合理」的錯

日文地名比對會安靜地給出合理但錯誤的答案。以下每一條都真的發生過。

**一、前綴贏過真地名。** 「東京銀座街日報社」比中的是「東京」，於是三幅畫全指到東京駅。
前綴要**剝掉而且排除在候選之外**——只做其中一件，它會再贏一次。這個錯犯了兩次。

**二、子字串。** 「大川端石原橋」比中「原橋」（世田谷），「ためいけ」比中「いけ」。
判準是前一個字的文字種類：同種類代表切在詞中間。
只對兩字名執行——三字以上的地名不會是別的詞的尾巴，一律執行會把増上寺、永代橋也擋掉。

**三、長度不是好判準，位置才是。** 第一版用「兩字以下一律不採」擋子字串，69 幅只中 10 幅：
日本地名本來就多半是兩個字（銀座・高輪・今戸・橋場・蔵前・大森）。
清親的題名幾乎都以地名開頭，所以**先頭比中的兩字名可信，句中冒出來的不可信**。

**四、同名多筆有兩種，混在一起就會誤判。** 隅田川 40 筆是同一條河被切成很多段（散佈 20km），
八雲神社 10 筆是十個不同的神社。前者要合併成一個地物，後者不能。判準是叢集直徑。
合併後取重心，但**種類要從最可信的那筆拿**：日本橋六筆裡有橋也有地鐵站，
取到站就變成「日本橋夜」畫的是地鐵站。

**五、只有眼睛抓得到的那個。** 「萬代橋朝日出」比到 OSM `way/1105144393`，在世田谷。
assert 過得了，因為它在畫框內。抓出來的方法是把 59 個點畫在水系上看：
其餘 68 幅全在舊市街與隅田川一帶，只有它落在西邊 4 公里的郊區，
而同一叢還有一座已因同樣理由否掉的常盤橋——那是戰後住宅區的橋群。

所以 `check-subjects.py` 是必要驗收不是加分項。
自動檢查抓得到「掉出畫框」，抓不到「落在錯的區」。

## 出版日期為什麼只有 4 筆

御届日期確實印在版面邊緣：id 1 是「明治九年八月廿一日御届」，
換算 1876 年 8 月 21 日，正好是光線画首發的那個月。但兩件事讓現在做全量判讀不划算：

- **奧付位置各幅不同**，右緣裁切只涵蓋一部分，12 幅樣本裡有 6 幅在左緣或下緣。
- **有些版子本身就沒填**：id 8 與 37 印了「明治　年　月　日」，數字空著。
  這不是讀不到，是版上就沒有。

全量判讀併進 Phase 2——那時 trim 本來就要逐幅分離四層（灰底 → 畫帖台紙 → 版畫紙 → 畫心），
邊欄已經切出來，不必為這件事把裁切做兩次。

🔑 **畫帖的排列不是編年的**：1＝1876、21＝1879、11＝1880、60＝1881。
⛔ 不可用畫帖順序推日期。
